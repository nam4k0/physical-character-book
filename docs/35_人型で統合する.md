## 2. MuJoCo humanoid の位置づけ

`Humanoid-v5` は、関節付きの人型モデルです（第11章）。

- 状態: ルートの高さ・向き、関節角・速度、など（第13章）。
- 行動: 各関節の目標角（PD制御、第12章）。

> 論文のキャラクタ（IsaacGym）とはモデルが違いますが、「剛体リンク＋PD制御＋AMP」という構成は同じです。第37章で SMPL 由来のモデルに差し替えます。

## 3. 参照モーションの準備

AMP には「本物の動き」が必要です（第19章）。論文は MoCap（SAMP）を使いますが、このミニ実装では次のどれかを使います。

1. **手続き生成**: 単純な歩行パターンを生成する（最も簡単）。
2. **サンプル運動**: MuJoCo 付属の歩行動作を利用。
3. **公開 MoCap**: 入手可能な歩行 MoCap をリターゲットする（第37章・付録D）。

```python
def _build_reference_motion(self):
    n = 2000
    self.ref_obs = torch.randn(n, self.obs_dim) * 0.1
    self.ref_amp_obs = self.ref_obs.clone()
```

> **正直な注意**: ランダムな参照モーションでは、識別器は「自然さ」を学べません。**質の良い参照モーションが AMP の要**です。この章の目的は、パイプラインを人型で通すことです。

## 4. タスク報酬 — 歩行

人型では、まず「歩く」を学ばせます（第32章の方針）。論文の sit/carry の報酬は第36章で扱います。

```python
def task_reward(self, obs, goal, action, next_obs):
    speed = self._forward_speed(next_obs)                     # 前進速度
    speed_reward = torch.exp(-2.0 * (self.target_speed - speed).pow(2))
    upright = torch.exp(-5.0 * next_obs[..., 1].pow(2))       # 直立
    alive = torch.ones_like(speed_reward)
    return 1.0 * speed_reward + 0.5 * upright + 0.1 * alive
```

第17章の「速度＋直立＋生存」のパターンです。

## 5. AMP を有効にする

`train.py` で `use_amp=True` にすると識別器が有効になります（第34章）。

```bash
uv run python scripts/train_05_humanoid_amp.py
```

## 6. 学習の観察

```mermaid
flowchart LR
    A["AMP なし<br/>跳ねる/不自然"] --> B["AMP あり<br/>自然な歩容"]
```

- AMP なしだと、速度報酬に最適化して「跳ねて進む」などの不自然な動きが出ます（第32章）。
- AMP ありだと、参照モーションに似た動きに引き寄せられ、**自然な歩容**になります。

## 7. 論文との対応

| このミニ実装 | 論文 |
| --- | --- |
| MuJoCo humanoid | IsaacGym の剛体人型 |
| 手続き生成/サンプル運動の参照 | SAMP・AMASS の MoCap |
| 速度＋直立＋生存の報酬 | sit/carry のタスク報酬（第25章） |
| 識別器（物体なし） | 識別器（物体なし、AMP 本来） |
| 数十環境（CPU） | 数千環境（GPU） |

## 8. つまずきやすいポイント

| 症状 | 対処 |
| --- | --- |
| 歩かずその場で立つ | 速度報酬を上げる、目標速度を確認 |
| 跳ねる/滑る | AMP の重みを上げる、参照モーションを改善 |
| すぐ転ぶ | 直立報酬・早期終了の調整 |
| 学習が遅い | 環境数・ステップ数を見直す（CPU の限界） |
